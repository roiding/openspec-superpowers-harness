# Skill TDD Loop

Use this reference when writing or revising skills.

## Loop

1. identify the missing or failing behavior
2. observe the baseline problem
3. write the smallest skill change that should fix it
4. validate structure and coherence
5. tighten wording when new loopholes appear

## Good reasons to create a skill

- the task repeats across projects
- the workflow has non-obvious judgment or steps
- a compact reusable guide will outperform re-explaining it each time

## Bad reasons to create a skill

- one-off project history
- generic knowledge the model already knows
- process clutter that belongs in repo docs instead
